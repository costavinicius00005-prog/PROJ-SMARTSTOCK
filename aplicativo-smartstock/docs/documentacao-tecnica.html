1. Visão geral e objetivo

O SmartStock Entregas é um aplicativo móvel para a última etapa do processo comercial: a entrega. Ele foi feito como produto independente do ERP e do backend atual. Na primeira versão roda com dados locais persistentes; na próxima etapa pode integrar qualquer backend Java/Spring Boot por API REST.

Princípio principal: as telas não conhecem SQLite ou HTTP. Elas dependem do contrato DeliveryRepository, permitindo trocar a fonte de dados sem reescrever a experiência do entregador.

Uma entrega finalizada não retorna ao fluxo normal no aplicativo. O servidor futuro deve validar transições e armazenar todo evento para auditoria.

6. Persistência e operação offline

O banco smartstock_delivery.db é criado pelo pacote sqflite dentro da área privada do aplicativo.

TabelaUso
deliveriesEntrega serializada em JSON e data de atualização.
delivery_eventsEvento de status com campo synced; forma a fila de operações.
  1. Ao atualizar uma entrega, o app grava o novo estado em deliveries.
  2. Na mesma transação, cria um evento pendente em delivery_events.
  3. A interface mostra a quantidade de atualizações aguardando servidor.
  4. Na integração futura, um serviço enviará os eventos em ordem e marcará cada item como sincronizado.
Limite atual: a fila é persistida e visível; o envio HTTP automático será ligado quando o backend Spring Boot fornecer os endpoints definidos nesta documentação.

8. Contrato de integração com Spring Boot

MétodoEndpointUso
POST/api/mobile/auth/loginLogin; retorna access token e refresh token.
POST/api/mobile/auth/refreshRenovação da sessão.
GET/api/mobile/routes/todayRota e paradas do entregador autenticado.
GET/api/mobile/deliveries/{id}Detalhe atualizado de entrega.
POST/api/mobile/deliveries/{id}/eventsInício, conclusão ou ocorrência.
POST/api/mobile/deliveries/{id}/proofsNome do recebedor e arquivo do comprovante.
POST/api/mobile/syncEnvio em lote de eventos feitos offline.
{
  "eventId": "uuid-gerado-no-celular",
  "status": "DELIVERED",
  "occurredAt": "2026-08-21T14:30:00Z",
  "note": "Recebido por Maria"
}

O campo eventId deve ser idempotente: se o aparelho reenviar o mesmo evento, o backend não pode duplicar a alteração.

9. Segurança e LGPD para produção

  • JWT curto com refresh token e HTTPS obrigatório.
  • Senha armazenada com BCrypt ou Argon2 no backend.
  • O servidor filtra as entregas pelo entregador autenticado; o Flutter não define a autorização.
  • Fotos ficam fora do banco, com acesso protegido.
  • Auditar status, usuário, data e origem da alteração.
  • Solicitar localização apenas com consentimento e finalidade clara.
